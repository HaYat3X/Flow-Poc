# 改善台帳

Flowシステムの動作確認で得た気づき・課題・問題を積み上げる台帳。社内システム開発を例題として各Skill・Policy・検査を動かし、その結果をここに記録する。

## 記載ルール

- 1件につき1つの見出しを追加する。見出しは `## IMP-連番 件名` とし、連番は3桁で振り直さない。
- 新しい件は末尾に追記する。既存の件を更新するときは本文を書き換え、経緯は「記録」に日付付きで追記する。
- 各件は次の項目を本文の後の箇条書きで持つ。
  - 日付: 気づいた日（YYYY-MM-DD）
  - 対象: 該当するSkill・Policy・検査・テンプレートなど
  - 事象: 何が起きたか、再現手順
  - 影響: 誰の何が困るか
  - 改善案: どう直すとよいか（未定なら「未定」）
  - 状態: 未着手 / 検討中 / 対応済み / 見送り
  - 記録: 日付付きの経緯
- 事実・推測・未確認事項を区別して書く。

## IMP-001 原本をINに置いただけで共通検査がエラーになる

使い方.mdの手順1は「依頼受付に記入し、原本をINへ置く」で、MAT台帳への登録はRequest Startの承認後に行う（request-start SKILL.md）と読める。一方、共通検査は `01_IN_入力/入力/` の全ファイルが入力資料一覧に載っていることを要求するため、手順1と手順2の間の状態がstrict検査で必ずエラーになる。手順上の正常な中間状態が検査で異常扱いになっており、誰がいつMATを採番するのかが文書間で揃っていない。

- 日付: 2026-10-08
- 対象: 使い方.md（手順1）、syncloop-flow-request-start、.tools/project_workflow_check.py（check_input_materials）、01_IN_入力/入力資料一覧.md
- 事象: 議事録を `01_IN_入力/入力/` に置いて `check --strict` を実行すると「入力資料一覧に登録されていません」で1件エラー（事実、再現済み）。今回はテストを進めるため、配置時にMAT-0001を「関連RQ: 未登録（依頼受付中）／unread／unreviewed」で仮登録して検査を通した。
- 影響: 受付担当が原本を置いた時点で検査が赤くなり、MATを先に採番してよいのか、Request Startを待つべきか判断できない。仮登録した場合、Request Start側の「未使用MATを選ぶ」手順と採番が二重になる可能性がある（推測）。
- 改善案: 未定。案A: 配置時にMATを採番する運用に統一し、使い方.mdの手順1とrequest-startの記述を合わせる。案B: 未登録原本は依頼受付の「関連資料」に記載があれば検査を注意（warning）に下げる。
- 状態: 未着手
- 記録:
  - 2026-10-08 起票（備品管理アプリ題材の入力配置時に検出）

- 日付: 2026-10-08

## IMP-003 依頼受付を誰が書くか、議事録との役割分担が曖昧

- 日付: 2026-10-08
- 対象: 01_IN_入力/依頼受付.md、使い方.md（手順1）
- 事象: 受付フォームの各見出しに何を書けば足りるか（原本参照だけでよいか、要約が必要か）の基準がない。
- 影響: 受付の記入負荷と、受付と原本の記載がずれた場合にどちらを正とするかの判断が残る（推測）。
- 改善案: 未定。Request Startで受付と原本の矛盾がどう扱われるかを確認してから検討する。
- 状態: 未着手

## IMP-004 Skill・Policyが `.agents/` と `.claude/` に二重配置され、呼び出し方の説明がCodex表記だけ

Claude Codeで使うため、`.agents/skills/` と `.agents/policies/` の複製が `.claude/skills/` と `.claude/rules/` に置かれた（2026-10-08時点で内容は完全一致、`diff -r` で確認）。正本がどちらか決まっておらず、片方だけ直すと内容がずれる。また、AGENTS.mdは呼び出し方を `$skill-name`（Codexの表記）でしか説明しておらず、Claude Codeでの呼び出し方（`/skill-name` または自然言語）が書かれていない。AGENTS.mdやSkillの本文は `.agents/policies/` を参照しているため、`.claude/rules/` の複製は参照先として使われていない（事実）。

- 日付: 2026-10-08
- 対象: AGENTS.md（Skillの利用）、使い方.md、.agents/skills・.claude/skills、.agents/policies・.claude/rules
- 事象: 利用者から「スキルの呼び出しはどうすればいいの？」と質問が出た。リポジトリ内の文書だけでは、Claude Codeでの呼び出し方が分からない。
- 影響: Skill・Policyを改訂したときに片方の更新が漏れ、ツールによって動作が変わる恐れがある（推測）。初めて使う人が呼び出し方で迷う。
- 改善案: 未定。案A: 正本を `.agents/` に決め、`.claude/` 側は同期スクリプトかシンボリックリンクで作る。案B: AGENTS.mdの「Skillの利用」に、ツール別の呼び出し方（Codex: `$name`、Claude Code: `/name` または自然言語）を1行ずつ追記する。
- 状態: 未着手
- 記録:
  - 2026-10-08 起票

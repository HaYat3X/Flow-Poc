# 現在地確認

AGENTS.mdの共通検査を実行し、エラー時も読取りを続ける。現在地・依頼一覧・Work一覧・対象RQ/Plan・関連案件Context、Workの入力・候補・終了判断を実体と照合する。Flow外の課題管理票の読取り・状態照合は必須にしない。

総合状態、次アクション、検査結果は必ず報告する。他は該当時のみ、依頼ごとの現在地、進行/保留Work、判断待ち、阻害要因、未同期候補/不整合を示す。総合状態は主対象RQ/進行RQ数/進行Work数/状態、依頼はRQ状態/Lifecycle/計画状態・範囲/現在Work/次ゲート、次アクションは優先度/対象/操作/理由/Skill/承認要否を示す。

- 未計画・needs_revisionはPlanを案内する。approvedの部分計画は実行可能であり、部分というだけでPlanを先行させない。
- approved/applyingの終了判断は終了同期の不足を示す。syncedなら保存済みnext_action・対象・理由を使う。一律のWork後レビューや再Closeは案内しない。
- 計画済み候補を消化しても依頼終了条件が未達ならplan_remainingとして未計画範囲を具体化する案内を示す。未判断なら不足確認を示し、勝手に終了としない。
- Flow内の判断待ち・blocking・Workの未解決事項を照合する。根拠がないのに「なし」としない。外部の課題・リスク・QAの担当・期限・対応状態は管理・判定しない。
- 進行計画のWBSのP-ID・親子関係・Workの状態を参照し、親行を件数だけで完了扱いにしない。

ファイルの変更、正本同期、計画や終了状態の判断・適用は行わない。不整合は具体箇所と影響を報告する。

新しいPlanが承認され、過去の終了判断よりplan_revisionが進んだ場合は最新計画と進行中Workを優先する。plan_remainingが解消済みなら旧案内を繰り返さない。未消化P-IDはWork開始、既存W-IDはそのWorkの継続を案内する。過去の終了判断そのものは書き換えない。

# Work開始

## 実行前

1. project-record-updates.md、cx-context.md、workspace-structure.mdを読む。
2. 対象RQがregistered/active/on_hold、planning_statusがapprovedであり、CTの進行計画が存在することを確認する。計画承認記録に提示中のPlan承認・区切り承認がある場合、その案はまだ正本でない。案に含まれるWorkは開始せず、計画の承認を先に案内する。部分計画も許可する。利用者が緊急作業の計画省略と理由を明示した場合だけ例外をRQと更新履歴へ記録する。
3. 進行計画の「今回始めるWork」から、状態が「未着手」で開始条件を満たす行を選ぶ。その行のP-IDをWorkのplan_item_idにする。旧形式（Work候補表のplanned）も読み取る。進行計画にない作業はWorkとして開始せず、Plan（区切り承認）を案内する。同じ行に既存W-IDがあれば重複開始しない。
	WBSの対応する作業パッケージ・先行と、進行計画の行の担当・予定・開始条件を確認し、先行作業の実際の完了をWBSとWorkから確認する。作業に必要な回答・前提・未解決事項を開始条件に照合する。Flow外の課題管理票の存在・ID・状態を開始条件にしない。予定日の到来だけで開始可能と判断しない。
4. 同じRQに終了Workがある場合はsyncedの終了判断と次アクションを確認する。continue_workで指定された候補か、承認済み拡張/改訂後の候補であることを確認する。別SkillによるWork後レビューは要求しない。並行Workを継続可能なら一つの終了Workのplan_remainingだけを理由に止めない。未同期候補・blockingなContext・行き先のない残件は止める。
5. RQ・Plan・現在地・索引の関連IDとパスから必要なContext、IN原本、Knowledge、Product、前Workの引継ぎだけを選ぶ。Contextは20セクションのメインとContext一覧を入口に、関連する詳細・CTXのみ読む。進捗・次アクションの要約は同期時点を確認し、実行状態はCT・Workの正本で確認する。索引と参照しなかった理由を残す。特化Skillは探索・提案しない。
6. Work一覧、直下・完了・アーカイブから未使用W-IDを選ぶ。

## 開始案と承認後

開始案はWorkセットで出す。「判断が要る点」は名前、関連RQ/P-ID、目的・期待する価値、対象・対象外、入力資料、Work全体の完了条件・確認方法、関連作業と、実行計画としての担当・期限・TODO、入力の根拠と版・時点とし、Work一覧・現在地・進行計画の行などの整合のための変更はファイル名だけを並べる。必要な成果物は完了条件に含める。対象と操作を特定した実行依頼は承認として扱う。

承認後にWorkフォルダを作り、[承認記録](assets/承認記録.md)に開始承認（承認済み、承認日時・承認者と立場・承認の発言・判断が要る点）を書き、[作業内容](assets/作業内容.md)、[入力一覧](assets/入力一覧.md)、[Work入力](assets/Work入力.md)、[作業メモ](assets/作業メモ.md)、[反映候補](assets/反映候補.md)を初期化する。終了判断と引継ぎはCloseで作成し、未承認の雛形を開始済みWorkへ置かない。

Work入力は1枚に、今回の目的、関連する現在値・前提・決定・リスク、作業条件、前Workの結果/残件、根拠表をまとめる。案件全体のContextや全原本のコピーは既定にしない。入力一覧へWI-IDで登録し、詳細の元ID・版・パスをreferenceで残す。版固定ができない資料だけcopy/snapshotする。要約してもunknown/conflictや例外・限界を落とさない。

作業内容にplan_item_id、目的・背景、作業対象・対象外、入力資料、完了条件・確認方法、関連作業を記録する。関連作業がなければなしとする。実行担当・作業期限・TODO・進捗・確認待ち・入力ベースラインは作業内容に記載しない。顧客の必須期限など要求上の制約は作業対象または完了条件に含める。

入力ベースラインは入力一覧とWork入力に記録する。作業メモの担当・作業期限、問い・Context観測対象・確認事項・TODO一覧・全TODOの記録先を実値で初期化する。提示された外部資料は必要な箇所から根拠として参照し、外部の課題管理をWorkへ複製しない。TODO一覧は現在の実行計画として更新し、変更理由・実績は日付付き作業記録に残す。RQ、進行計画の行（状態を開始済み、Work IDを記入）、WBSの紐づくWorkと状態（未着手なら進行中）、Work一覧、現在地、更新履歴を整合し共通検査を実行する。この行の更新は状態更新であり、plan_revisionは進めない。更新履歴の根拠には `W-xxxx_承認記録#A-01` を書く。TODO実行・成果作成・Work終了は行わない。

Work中に目的・範囲・完了条件を変える場合は、同じ承認記録に変更承認を提示中→承認済みで追記してから作業内容を直す。進行計画やWBSに波及する場合は計画セットの承認も受ける。TODOの追加・分割・順番の変更は承認不要で、作業メモに記録する。

Context本文と反映候補はcx-context.mdとテンプレートに沿った自然言語で作成する。内容・理由・影響を本文で説明し、追跡用IDと属性は補足に置く。承認用の反映案も同じ文章形式を維持し、管理番号と横長の表だけの文書に変換しない。

# 作業メモ

この文書は、Workの実行計画・進捗と、作業で得た事実、判断、失敗、未解決事項を残す一次記録である。現在の実行計画とTODO状態は状況に応じて更新する。日付付き作業記録は削除・上書きせず、意味ある作業単位の直後、およびセッション終了・最終報告の前に追記する。

Context、意思決定、Knowledge、Productへの反映候補があれば同じWorkの `反映候補.md` に内容を記録し、このログには候補IDを残す。候補は正本への反映完了を意味しない。課題・リスク・QAの対応管理はFlow外で行い、Flow側では抽出・登録・状態更新を行わない。

## TODO一覧

現在の実行計画を記載する。TODO IDはWork内で一意にし、下の作業記録から参照する。TODOごとの完了条件は `作業内容.md` のWork全体の完了条件を実施・確認するための具体的な単位とする。担当・予定がTODOごとに異なる場合は、このセクションに記載する。

| TODO ID | TODO | 完了条件 | 関連するWork全体の完了条件 | 状態 |
| ------- | ---- | -------- | ---------------------------- | ---- |
| T-001 | 未設定 | 未設定 | 未設定 | 未着手 |

状態は `未着手`、`作業中`、`保留`、`完了`、`中止` のいずれかを使う。既存TODOでは扱えない作業が判明した場合は追加し、完了条件や担当・期限が異なる場合は必要に応じて分割する。新しいTODOには新しいIDを付け、下の作業記録に追加・分割・変更の理由と影響を残す。保留・引継ぎ時は、理由、未解決事項、次の対応、引継ぎ先を記録する。

TODOがすべて完了していても、Work全体の完了条件を満たした確認がなければWorkは完了としない。必要なTODOが未完了なら作業を継続する。不要になったTODOは中止理由を記録し、Work全体の完了条件を満たすかで判断する。

## TODOごとの作業記録

TODOごとに1セクションを作成する。同じTODOを続ける場合は、該当セクションへ `#### 追記 YYYY-MM-DD HH:MM` の見出しを追加する。成果物は必要に応じてWorkフォルダの `作業成果/` または案件側の運用先に作成し、ここには参照先と完了条件の確認結果・根拠を記録する。入力の追加・差替えは `入力/入力一覧.md` に登録し、理由と影響を該当TODOの記録へ追記する。

通常のTODOと重要な調査・判断で記録形式は分けない。詳細な分析や資料が必要な場合は、Workフォルダ内の任意ファイルへ作成し、該当TODOの「根拠」または「実施内容」から参照する。候補IDはWork内で一意にし、`C-CTX-001`、`C-DEC-001`、`C-RSK-001`、`C-ISS-001`、`C-KNW-001`、`C-PRD-001` の形式を使う。

TODOに属さないWork全体の記録（Work開始時・終了同期時の経緯など）は、TODOセクションとは別に `### Work開始記録`、`### Work終了記録` のような見出しを作り、その下に日付付きで追記する。これらの記録にはTODO用の必須欄を求めない。

### TODO T-001：TODOの題名

#### 追記 YYYY-MM-DD HH:MM

##### TODOの作業内容

TODOで何を行うかを記録する。

##### 実施内容

行った操作、確認手順、入力などを記録する。

##### 観測事実

実際に確認できた結果だけを記録する。

##### 解釈・暫定判断

観測事実からの作業上の解釈、暫定判断、次に行うことを記録する。ここへの記載だけでは正式な意思決定にしない。

##### 根拠

参照した資料、ログ、成果物、確認結果などを記録する。

##### 未解決事項・次の対応

残った問題、確認待ち、次回対応、必要なら引継ぎ先を記録する。なければ `なし`。

このWork内で対処できるものはTODOで扱う。外部での判断・対応が必要なものは、作業への影響・確認先・次の対応・引継ぎ先を残す。外部資料の参照先が提示されている場合は根拠として添えるが、外部の管理票の登録・更新は行わない。

##### 反映候補の確認

Context、意思決定、Knowledge、Productの候補があれば、該当する `反映候補.md` の候補IDを列挙する。なければ `なし`。Flow外の課題管理票への登録・更新を候補に含めない。

# 記録同期

project-record-updates.md、cx-context.md、workspace-structure.mdを読み、利用者の依頼からinput/decision/closeを特定する。対象・操作を特定した既存承認を再承認させない。Skill選択だけでは未判断内容を正式化しない。

## 入力同期（input）

受付時原本はINの入力へ置きMATを発行して入力資料一覧とRQを関連付ける。Work開始後の追加原本は対象Work入力へ置きWIを発行し、入手元・確認日・元資料名・実ファイル配置先・版・時点・用途・確度を入力一覧へ記録する。既存MATを使う場合は元MATも記録する。Work内複製物にMATを重複発行しない。

追加・差替えの理由と作業影響を作業メモに追記する。必要ならWork入力要約の新版を作り、旧版と参照を保持する。ファイルの存在・所在など意味判断を伴わない登録に追加承認は不要。原本は上書き・削除しない。未処理の終了判断があればinvalidatedとしてClose再確認が必要なことを報告する。Workの状態は閉じない。

## 途中の判断同期（decision）

課題・リスク・QAの対応管理はFlow外とし、管理票の作成・登録・更新・同期は行わない。提供された回答・対応結果から仕様・方針・計画の変更が生じた場合は、その変更だけを通常の承認済み判断として同期する。外部の対応状態を独自に判断しない。

Context等の候補を同期する場合は、対象候補、判断者・日、処理結果・理由・反映先を確認する。Workの候補はWorkの承認記録に途中Sync承認（反映する候補と反映先を判断点にする）を提示中→承認済みで残してから反映し、更新履歴の根拠に `W-xxxx_承認記録#A-xx` を書く。対象正本を再読し競合がない場合だけ承認された差分を反映する。Context/意思決定は候補種別と許可された反映先セクション番号からCXの反映先を決める。分離済みセクションは詳細側だけを正本として更新し、メインは要約を同期する。Knowledgeは該当分類の[テンプレート](assets/knowledge-templates/)を使う。適用条件・根拠・例外を維持する。意味が同じ既存CTXは同一ID・現在の配置で更新する。

回答や対応から確定した要求・仕様・意思決定の変更は、提供された資料・Workを根拠にContextへ反映する。外部管理票の存在・ID・状態は反映の必須条件にしない。現在地に影響する変更があれば要約を更新し、更新履歴に記録する。

候補処理履歴に同期済みと反映先ID・パスを追記し、索引・トレーサビリティ・現在地・更新履歴を整合する。未判断候補は適用せず、対象と不足を示してCloseへ戻す。Workの終了状態や次アクションを独自に決めず、終了判断があっても終了同期へ切り替えない。判断後の前提変更はClose/Planに再確認を案内する。

## 終了同期（close）

work-close-contract.mdを読み、その手順と版検証を実施する。終了判断.md、承認封印、引継ぎ、版表、終了反映案を確認する。approvedはbefore、applyingからの再開はresumeで検査し、syncedなら適用済みと報告する。

検証成功後だけapplyingにして承認用targetを適用し、候補同期・全Work文書の状態・完了フォルダ移動・関連参照・計画の消化状態・CTの4台帳を揃える。after検証が成功したらsyncedと実日時を記録し、共通検査を実行する。候補ゼロも同じ完了経路を使う。想定外の差分や不足は完了確定を止め、具体的な箇所を示す。

終了判断で指定されたnext_action・対象・理由を案内する。continue_workは進行計画の未着手の行（P-ID）ならWork Start、既存W-IDならそのWorkの継続、plan_remainingはPlanで次の区切りの進行計画（区切り承認）、replanはPlanでWBSの見直し（Plan承認）、request_closeはRequest Close、resolve_blockerは不足確認を案内する。plan_remainingでは未計画の具体範囲と使うWork結果を示す。Closeの再依頼や一律のPlanレビューは要求しない。

## Context配置の保守と確認

Contextの反映後はcx-context.mdの文字数計測で、メインの1セクション6,000文字超または本文全体25,000文字超を確認する。超過セクション、次に本文の大きいセクションから、固定の `NN_セクション名.md` へ詳細を分離する。メインは20セクションと案件識別情報を保持し、分離部分を短い要約・同期時点・詳細リンクにする。基本情報・進捗・次アクション・3分サマリは分離せず要約を短く整える。内容とIDは変えず、一覧・参照・更新履歴・context_layoutを揃える。自動再結合しない。

メイン13・14には案件全体への影響・前提・未決事項・確定した結論の要約を置く。Flow外の管理票の担当・期限・対応状態は複製しない。

1・12・17・20と分離済みセクションの要約は、CT・Work・詳細正本から更新要否を確認する。参照元・対象ID・同期時点を残し、独立管理しない。候補ゼロでも実行状態の変更による要約差分を確認する。終了同期では要約、詳細分離、参照修正がCloseの承認用targetに含まれることを確認し、承認後に独自の要約・次アクションを追加しない。不足があればCloseへ戻す。

確認範囲は対象RQ・Workと関連ID・パス。案件全体は利用者が依頼した場合だけ広げる。入力の版・所在、正本/台帳の一致、候補同期、根拠、承認済み適用範囲を確認し、AGENTS.mdの共通検査を実行して結果を報告する。

Context本文と反映候補はcx-context.mdとテンプレートに沿った自然言語で作成する。内容・理由・影響を本文で説明し、追跡用IDと属性は補足に置く。承認用の反映案も同じ文章形式を維持し、管理番号と横長の表だけの文書に変換しない。

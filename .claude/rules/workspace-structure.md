# ワークスペース構成Policy

| 領域 | 責任 |
| --- | --- |
| `02_CT_管理/` | 現在地、依頼一覧、Work一覧、更新履歴の4台帳と、依頼本文・進行計画の正本 |
| `01_IN_入力/` | 依頼受付、受付時の原本と入力資料一覧 |
| `03_CX_コンテキスト/` | 育てる案件概要、要求・前提・制約・方針・意思決定の現在値。課題管理から確定した結論はここに反映する |
| `04_WK_作業/` | 1枚のWork入力、追加原本、作業過程、成果、終了判断、1枚の引継ぎ |
| `06_PD_プロダクト/` | 実装・リリースとの関係 |
| `07_KN_ナレッジ/` | 再利用できる承認済み知識 |
| `99_AX_アーカイブ/` | 終了依頼・計画・Work、専用受付原本、整理前記録、失効したContext |

## 配置と移動

- 案件概要の入口は `03_CX_コンテキスト/プロジェクトコンテキスト.md`。20セクションのメインを保持する。詳細は1セクション6,000文字超またはメイン本文25,000文字超でcx-context.mdの固定セクション別ファイルへ分離する。メインと案件識別情報は残し、詳細は要約・同期時点・リンクにする。案件概要・意思決定の正本をCTに複製しない。
- 課題・リスク・QAの対応管理はFlow外で行う。Flow内に管理票を作成せず、外部管理票の登録・更新・同期を行わない。作業への影響・未解決事項・引継ぎはWork、確定した仕様・方針はCXに置く。提示された外部資料は根拠として参照できるが、その存在をFlowの必須条件にしない。
- 依頼本文の文書名は「プロジェクト計画」とし、`02_CT_管理/依頼/RQ-xxxx_プロジェクト計画.md` に置く。WBSは `02_CT_管理/進行計画/RQ-xxxx_WBS.md`、次の区切りまでの進行計画は `02_CT_管理/進行計画/RQ-xxxx_進行計画.md` に置く。RQ-ID・依頼フォルダ・document_type: requestは維持する。既存文書は実際の参照先を使い、自動改名しない。これらは案件Contextの自動分割対象ではない。作成・改訂時は案件Contextへの反映要否を確認し、本文や個々の実行状態をCXへ複製しない。期間・フェーズ・進捗・次アクションは参照元と同期時点付きの短い要約としてのみCXに置ける。
- プロジェクト計画は対象システムの目的・範囲・成果物・受入条件・責任者・制約を整理し、WBSは依頼の終了までを見渡す作業パッケージの表とガント、進行計画は次の区切りまでの実行計画とする。案件共通の方針・体制・判断権限はCXを参照する。WBSはP-IDで親子関係を持ち、紐づくWorkにW-IDを記す。ガントはWBSの表から検査ツールで生成する。実行TODO・実績はWorkへ置く。旧計画の移行時はP-ID・完了結果を失わない。
- 受付原本は `01_IN_入力/入力/`、Work開始後の直接受領原本は対象Workの `入力/` に保管する。上書き・削除しない。
- Work開始時に関連する現在値と前Workの引継ぎから `入力/Work入力.md` 1枚へ必要事項を要約する。元資料の全量コピーを既定にしない。根拠は元ID・版・時点・パスで追跡する。
- `入力/入力一覧.md` は要約と必要な詳細資料の索引。要約は `snapshot`、詳細は原則 `reference`。版固定が参照だけで保証できない場合のみcopy/snapshotを使う。
- Workの成果はWork内または案件側の既存運用先へ置く。作成したものと配置先の参照を残す。成果を同じWorkの入力として二重登録しない。
- 承認記録は承認の対象と同じ場所に置く。依頼の承認は `02_CT_管理/依頼/RQ-xxxx_依頼承認記録.md`、WBS・進行計画の承認は `02_CT_管理/進行計画/RQ-xxxx_計画承認記録.md`、Workの承認は各Workフォルダの `承認記録.md`。依頼本文・計画と同じ接頭辞を持つが、依頼・計画の文書としては数えない。
- Closeは `終了判断.md` と `引継ぎ.md` を作成し、適用後の正本・台帳・Work文書の承認用差分を `終了反映案/` に保存する。承認後の適用はSyncだけが行う。
- 終了同期で `completed` を適用したWorkは `04_WK_作業/完了/` へ移動し、索引と相対・外部参照を同じ変更単位で更新する。Work文書の中でWork自身を指すパスはWorkフォルダからの相対パスで書くため、移動しても書き換えない（project-record-updates.md）。書き換えが要るのは、台帳・Context・Knowledgeなど、Work外からWorkを指す参照だけである。他の状態は直下に残す。
- 依頼終了時は依頼本文・依頼承認記録・対応する進行計画・WBS・計画承認記録と終了サマリを `99_AX_アーカイブ/依頼/RQ-xxxx_依頼名/` 直下へ、関連する終了済みWorkを `work/` へ移す。対象依頼専用の受付原本は `input/` へ移し、共有・継続利用資料はINに理由付きで残す。案件全体のContext、Product、Knowledgeは移動・初期化しない。
- 初期化/圧縮前の依頼受付・入力資料一覧・現在地・依頼一覧・Work一覧・更新履歴は、同じAX内の `記録/` に同名でバイト列保存する。履歴スナップショットと現行正本を区別する。原本と記録の保存前SHA256、全移動先・残置先を終了サマリの参照移動対応に記録する。保存後に対象受付だけを初期化し、MAT索引を維持してCTを残る依頼/Workの現行表示へ圧縮する。詳細はproject-record-updates.mdに従う。
- Work内の入力要約・引継ぎ・終了反映案は、その時点の記録であり案件の正本を置き換えない。移動時にも根拠・承認を追跡できるようにする。

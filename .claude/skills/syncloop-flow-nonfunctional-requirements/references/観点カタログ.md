# 観点カタログ

非機能要件を聞き取るときの、章ごとの確認観点・質問・「よくある値」の例です。

- 「よくある値」は、利用者が答えやすいようにする**選択肢の例**です。回答を得るまで本文には入れません。
- 観点は、実際の案件の非機能要件資料と、IPA「非機能要求グレード」の6大項目（可用性、性能・拡張性、運用・保守性、移行性、セキュリティ、システム環境・エコロジー）を下敷きに、一般的な言葉に直したものです。特定の会社の様式や製品名は含みません。
- GIS固有の観点（地図表示の性能、背景地図のライセンス、座標系など）は含みません。必要なときは、利用者の指示で章に足します。
- 案件に当てはまらない観点は、聞かずに「対象外（理由）」にしてよいか利用者に確認します。

## 1. システム構成

| 観点 | 質問 | よくある値の例 |
| --- | --- | --- |
| 設置場所 | サーバは顧客の社内、データセンター、クラウドのどれに置きますか | 社内サーバ / クラウド / ホスティング |
| サーバ | OSとスペック（CPU・メモリ・ストレージ）の指定はありますか | 顧客の標準構成に合わせる |
| クライアント | 利用する端末とOS、ブラウザの指定はありますか | Windows 10/11、Edge・Chrome |
| 基盤 | 使うミドルウェア・データベースの制約（バージョン・ライセンス）はありますか | 顧客の既存契約に合わせる |
| 連携 | 他システム・外部サービス（メール、認証、API）とつなぎますか | メール送信、SSO |
| 公開範囲 | 社外からアクセスしますか。通信の経路は | 社内LANのみ / VPN経由 / インターネット公開 |

## 2. 可用性

| 観点 | 質問 | よくある値の例 |
| --- | --- | --- |
| 稼働時間 | 利用する時間帯は。止められない時間帯は | 24時間365日 / 平日9〜18時 |
| 計画停止 | 保守のために止めてよい時間帯と頻度は | 月1回、夜間 |
| バックアップ | 何を、どの頻度で、どこに、何世代取りますか | 毎日、別ストレージに7世代 |
| 復旧目標 | 障害時にいつまでに（時間）、どの時点まで（データ）戻す必要がありますか | 当日中に復旧、前日分まで |
| 災害対策 | 拠点の被災を想定した対策は必要ですか | 不要 / 遠隔地バックアップ |

## 3. 性能・拡張性

| 観点 | 質問 | よくある値の例 |
| --- | --- | --- |
| 利用者数 | 登録する利用者の総数は | 〜20名 |
| 同時アクセス | 通常時とピーク時の同時利用者数は。ピークが来る時間帯は | 通常7名、ピーク20名 |
| 応答時間 | 主要な操作の目標時間と、その測り方（何件のデータで、どの端末で）は | 検索3秒以内（1万件、標準端末） |
| データ量 | 現在の件数と、1年・5年後の増加見込みは | 現在10万件、年1万件増 |
| 大量処理 | 帳票やバッチで、最大何件を何分以内に処理する必要がありますか | 1万件の帳票を10分以内 |
| 将来の増加 | 利用者や機能の拡大予定はありますか | 2年後に2拠点追加 |

「業務に問題がない程度」のような答えは、測れる値に言い換える案を添えて確認事項にします。

## 4. セキュリティ

| 観点 | 質問 | よくある値の例 |
| --- | --- | --- |
| 認証 | ID・パスワード以外の方式（SSO、多要素）の要求は。パスワードの強度・有効期限は | 英数記号8桁以上、90日で変更 |
| 権限 | 利用者の役割ごとに、使える機能と見えるデータを分けますか | 一般・管理者の2種類 |
| セッション | 無操作で自動ログアウトする時間は | 15分 |
| 監査ログ | 何を（ログイン、操作）、どの形式で、どこに、何日保持しますか | ログイン・操作履歴、365日 |
| 通信 | 通信の暗号化は必要ですか | HTTPS |
| 外部公開 | インターネットから見えますか。公開しない場合、第三者検証は省いてよいですか | 非公開のため実施しない |
| 脆弱性対策 | 診断や第三者検証を実施しますか。誰が行いますか | 実施せず / リリース前に診断 |
| ウイルス対策 | サーバ・端末の対策ソフトは誰が用意しますか | 顧客が導入済み |
| アクセス制御 | 他システムとの間のFW・ポートの制御は誰が行いますか | 顧客の情報システム部門 |
| リモート保守 | 本番環境に保守者がどう接続しますか。誰が許可しますか | リモート接続ツール、都度許可 |

## 5. 運用・保守

| 観点 | 質問 | よくある値の例 |
| --- | --- | --- |
| 監視 | ハード（死活）とアプリ（ディスク容量など）を監視しますか。誰が行いますか | 顧客が容量を監視 |
| 問合せ | 窓口、受付方法、対応時間は | 電話・メール、営業日9〜17時 |
| リリース | 本番へ反映してよい時間帯は | 昼休み、または終業後 |
| 保守範囲 | 保守で対応する内容と、別途費用になる内容は（契約側に記載し、ここでは参照のみ） | 契約書を参照 |
| 運用手順 | 運用手順書や引継ぎは必要ですか。誰が作りますか | 運用手順書を納品 |

契約不適合責任、保守契約の期間・費用・対象範囲、契約上の検収条件は、契約書・受託条件を参照し、この章には書きません。

## 6. 移行

| 観点 | 質問 | よくある値の例 |
| --- | --- | --- |
| 対象 | 移行するデータ・ファイルの種類は | マスタ、取引データ、添付ファイル |
| 範囲 | 過去データはいつ分から移しますか | 全期間 / 直近3年 |
| 方式 | 一括切替か、段階切替か。並行稼働はありますか | 一括切替 |
| 時期・停止時間 | 切り替えられる日時と、止めてよい時間は | 土日、停止は2日以内 |
| 立会い | 切替直後の立会いや問合せ受付は必要ですか | 1週間、遠隔で一次受付 |
| 支援期間 | 切替後の支援はいつまでですか | 本稼働後3か月 |
| 切戻し | 失敗時に戻す条件と方法は | 判定会議で決め、旧環境へ戻す |

## 7. テスト・受入

| 観点 | 質問 | よくある値の例 |
| --- | --- | --- |
| システムテスト | 誰が、どの環境・データで、どれくらいの期間で行いますか | 自社が開発環境で2か月 |
| 受入テスト | 顧客は、どの環境・データで、どれくらいの期間で行いますか | 顧客が本番相当環境で1か月 |
| 合否基準 | 受入の合格をどう判断しますか（重大不具合0件、シナリオ全件合格など） | 重大0件、シナリオ全件実施 |
| 現行比較 | 現行システムとの出力比較は必要ですか | 帳票を新旧で比較 |
| 自社で確認できないもの | 自社環境で確認できず、受入で確認するものはありますか | 印刷レイアウト、実機連携 |

受入の合否基準は、顧客が判断できる言葉で書きます。

| --- | --- | --- |

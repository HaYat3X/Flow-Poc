# RQ-TBD 終了サマリ

## 終了理由と結果

終了条件ごとの確認結果・根拠、完了または中止の理由を記録する。

## 関連Workの最終状態

全関連WorkのW-ID・最終状態・synced終了判断・移動先を記録する。Workがなければ理由付きでなしとする。

## 作業結果・Product・Knowledge

成果と承認済み反映先を記録する。該当しなければ理由付きでなしとする。

## 残件と引継ぎ先

残件ごとの影響・引継ぎ先ID・次の対応を記録する。なければなしと明記する。

## 継続して参照するContext

継続するCTX-ID・適用範囲・正本の参照先を記録する。依頼終了だけを理由に有効なContextを失効させない。

## Context反映の最終確認

全観点にreflectedまたはno_changeと根拠を記録する。no_changeには更新不要理由を必ず記録する。未同期・未判断があれば終了処理を止める。

| 未反映候補・残件 |  |  |  |
| 進捗・次アクション・サマリ |  |  |  |
| 参照・トレーサビリティ |  |  |  |

## 入力の保存と初期化

対象MAT-ID・受付原本の移動先、共有/継続利用資料の残置理由、受付フォームの初期化または別依頼のため維持した理由を記録する。MAT索引と発行済みIDは維持する。

## 管理文書の整理

整理前記録は履歴スナップショット。現行の依頼一覧・Work一覧・現在地・更新履歴それぞれについて、除去/圧縮した範囲と残した情報・理由を記録する。

## 参照移動対応

パスはルート相対・区切りは/とする。種別はinput/record/request/plan/work。inputとrecordは保存前SHA256を記録する。他はnone。残置原本は旧参照と現在の参照先を同じ値にする。過去の封印や承認内容に残る旧パスはこの対応から追跡する。

| 旧参照 | 現在の参照先 | 種別 | 移動前SHA256 |
| --- | --- | --- | --- |

## 承認と検査結果

承認範囲・根拠、strict検査のコマンド・実行日時・結果を記録する。承認者/日時はfrontmatterにも記録し、保存・整理・検査が成功した場合だけcleanup_statusをcompletedとする。

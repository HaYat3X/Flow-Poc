# 取り決め項目と質問

共通化するのは確認する項目と質問であり、条件の答えではない。資料に答えがあれば該当箇所を記録し、答えがなければ未確認として必要な質問を提示する。全質問を一度に利用者へ投げず、範囲・責任・完了条件に影響するものを優先する。

## 9分類

| 分類 | 整理する内容 | 確認質問 |
| --- | --- | --- |
| 目的・利用範囲 | 業務上の目的、利用者、部門、拠点、用途 | 誰がどこで何のために使うか。目標と保証する成果が区別されているか。グループ会社や外部提供も含むか |
| 対象・対象外 | 業務、機能、工程、移行、教育、外部連携、対象外 | 今回どこまで扱うか。対象外や境界作業は何か。他案件・他部門・他社とのつなぎ目を誰が担うか |
| 前提・依存条件 | 根拠資料、提供情報、環境、他作業への依存 | どの資料の何版を前提にするか。誰がいつまでに何を提供するか。提供遅れ・品質不足・前提変更時はどう判断するか |
| 役割・責任 | 作業者、主担当、判断者、承認者、協力者 | 誰が作業し、誰が判断・承認するか。「支援」は具体的に何を何回どの方法で行うか。責任が重複・欠落していないか |
| 成果物・完了条件 | 引渡すもの、実施作業、確認方法、品質・受入基準 | 何を渡す、または実施するか。何を誰が確認したら完了か。不適合や未解決事項が残る場合の扱いは何か |
| 期限・節目 | 提供、レビュー、仕様確定、納入、受入、作業期間 | 判断と情報提供は作業開始に間に合うか。レビュー期間は確保されているか。分割引渡しと完了承認が対応するか |
| 変更時の扱い | 追加要求、前提変更、遅延、中断、影響評価、合意 | 誰が変更を受け付け、影響を評価し、採否を決めるか。費用・日程・範囲の見直しは誰と合意するか。合意前の着手をどう扱うか |
| 環境・利用条件 | 場所、アクセス、貸与、ライセンス、データ、情報取扱い | 誰がいつ環境を準備するか。利用制限・期間は何か。権限付与、返却、廃棄、機密・個人情報の取扱いは明確か |
| 意思決定・連絡 | 窓口、権限、会議、記録、エスカレーション | 仕様・費用・日程を誰が決められるか。複数部門の意見を誰がまとめるか。決定はどこに記録し誰へ伝えるか |

9分類を必ずレビューし、未記載の分類を黙って省略しない。「記載なし」は情報不足であり「対象外」ではない。

## 立場・案件形態の読み替え

| 場面 | 読み替え・注意点 |
| --- | --- |
| 受注側 | 自社の実施範囲だけでなく、相手方が行う準備・確認・承認とその期限も整理する。相手方への費用負担・免責を当然の条件にしない |
| 発注側 | ベンダーの説明にない作業を契約内と推測しない。発注側のデータ準備、業務判断、受入、他ベンダー調整の負担も確認する |
| 内製 | 当事者を業務部門・開発部門・運用部門などで記す。契約番号・甲乙・検収を強制せず、予算・体制・引渡し・完了承認に読み替える |
| 請負・準委任 | 契約の実際の内容を確認し、成果完成責任や検収の有無を名称だけで断定しない。必要なら法務・調達へ確認する |
| 反復開発・PoC | 一括仕様凍結を前提にせず、対象期間・反復・評価項目・判断の節目を整理する。PoC結果から本番品質や後続開発を保証しない |
| パッケージ・SaaS | 製品の標準機能、設定、個別開発、利用契約、提供元の制約、運用の責任分界を分ける |

目的の達成指標と契約・作業上の保証を混同しない。工程名・役職名は現場の用語を使い、別名がある場合は対応表を残す。

## 必要な場合だけ追加する確認

| 観点 | 追加する契機 | 主な確認内容 |
| --- | --- | --- |
| 知的財産・利用許諾 | ソース、成果物、第三者製品を利用・提供する | 権利帰属、利用・改変・再配布範囲、ライセンス、引渡し対象 |
| 個人情報・データ保護 | 実データや機密情報を扱う | アクセス、持出し、保存場所、委託先、削除、事故時の連絡 |
| 保守運用 | 引渡し後の対応を含む、または範囲が曖昧 | 監視、問合せ、障害・不具合対応、期間、時間帯、サービス水準、別契約との境界 |
| 複数契約・複数ベンダー | 連携・工程・責任が分割される | 各契約の対象、統合・調整責任、依存期限、全体の完了判断 |
| 法的意味のある条件 | 免責、損害、費用負担、保証、みなし検収などが現れる | 根拠契約、適用範囲、当事者の合意、専門担当の確認 |

これらを網羅的な法律・調達チェックリストと称さない。質問の提示はできるが、専門的な妥当性や適切な条文をこのSkillで確定しない。

# テストケース設計

開始済みのテスト設計Workについて、要件・設計・レビュー記録と実装成果物を分けて確認し、画面で観測できるテストケースを作成するPoCです。対象はHTMLモックまたはWeb画面のブラックボックステストであり、テスト自動実行、API・バッチ・帳票・非機能テスト、`05_AT_成果物/DL_デリバリー/05_テスト/` への登録は扱いません。

## 実行前提

- `syncloop-flow-work-start` によりテスト設計Workが開始済みであり、対象Workの `作業内容.md` と `作業メモ.md` がある。
- 対象成果物、版、テスト目的、テストレベル、対象・対象外、根拠資料が利用者またはPMにより特定されている。
- 出力前に利用者またはPMから、テストケース案、要確認事項、出力先について明示承認を得る。

## 設計手順

1. 対象Work、対象成果物と版、要件・設計・レビュー記録、対象外を確認する。実装からのみ分かる振る舞いは、期待結果として確定しない。
2. 機能・操作・状態・制約を、根拠ファイルと人が戻れる箇所とともに整理する。期待結果の優先順位は、要件・受入条件、承認済み設計、承認済みレビュー・明示合意、実装成果物の順とする。
3. 正常、必須入力、境界値、選択肢、状態遷移、データ有無、変更、削除、取消、対象切替から、根拠のある観点だけを選ぶ。境界値・文字種・桁数・重複・権限は明示根拠がある場合だけ確定ケースにする。
4. 画面で観測できる一つの結果ごとに、ID、対応要件、画面・機能、分類、目的、前提条件、具体的な操作手順、入力値、期待結果、根拠、確度を含む `テスト設計データ.json` 案を作る。操作手順で「同上」「同様」を使わない。
5. 利用者へ、対象、根拠資料、観点数・ケース数、要確認事項、対象外、更新するもの（Work内の3ファイル）と更新しないもの（原本・実装・正式成果物）を提示する。
6. 承認後、`scripts/test_case_markdown.py validate`、`render` を実行して `テスト設計データ.json`、`テスト観点一覧.md`、`テストケース.md` をWork内へ作成する。作業メモには、入力資料、件数、検査結果、要確認事項を追記する。

## 品質と停止条件

- `確定` ケースは、実装以外の上位根拠を必ず持つ。上位根拠がないケースは `要確認` として扱う。
- スクリプトは未承認データ、必須項目不足、ID重複、禁止表現、完全一致・正規化後一致の重複、対象外要件の混入、50件超過、未分類の対象要件を停止する。
- `render` は既存の `テスト観点一覧.md` または `テストケース.md` を上書きしない。差分を確認して利用者の明示判断を得る。
- 対象Work、対象版、テスト目的、期待結果の上位根拠、出力先のいずれかが未確認なら、確定ケースの出力を止める。

## PoCコマンド

```powershell
py -3 scripts/test_case_markdown.py validate --data <テスト設計データ.json>
py -3 scripts/test_case_markdown.py preview --data <テスト設計データ.json>
py -3 scripts/test_case_markdown.py render --data <テスト設計データ.json> --output-dir <Workフォルダ>
```

データの項目と許可値は [テスト設計データ.schema.json](references/テスト設計データ.schema.json)、観点の適用基準は [テスト観点カタログ.json](references/テスト観点カタログ.json) を参照する。

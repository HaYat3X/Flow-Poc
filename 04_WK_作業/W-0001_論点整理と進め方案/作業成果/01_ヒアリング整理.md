# 初回ヒアリングの整理（備品管理アプリ 要件定義）

> 【ダミー】Flow動作確認テスト用の架空案件。会社・人物・数値はすべて架空。

- 作成: 2026-10-08（W-0001 T-001）
- 根拠: 2026-10-01 初回打ち合わせ議事録（MAT-0001）。以下は議事録の内容を部署別に並べ直したもので、新しい事実は加えていない。当社の解釈は「当社の整理」と明記する。

## 1. 現状の管理方法

| 対象 | 管理している部署 | 管理方法 | 現状の問題 |
| --- | --- | --- | --- |
| 什器・プロジェクター・カメラ・予備PCなど | 総務部 | Excel台帳（シート約12枚、約1,200件）、管理番号シール | 実物との一致は7〜8割程度（松本主任の感覚）。古い備品はシールの剥がれ・番号重複がある |
| 貸出（プロジェクター、予備PC、カメラ、測定器の一部など） | 総務部 | 紙の貸出簿 | 返却忘れ・所在不明が月に数件 |
| 工場の工具・測定器 | 各工場の製造課 | 工場ごとの独自Excel | 総務の台帳と別管理 |
| 業務PC・ネットワーク機器 | 情報システム課 | 情シスの資産管理ツール | 備品アプリと二重管理にしたくない |
| 固定資産（10万円以上中心） | 経理部 | 固定資産台帳 | 総務の台帳と別管理で、毎年突き合わせが必要 |
| 棚卸 | 総務部2名 | 年1回（3月末）、3拠点を巡回 | 毎回約2週間かかり、差異を説明できない |
| 購入から登録 | 総務部 | 申請はメール、登録はExcel | 分断されていて登録漏れが出る |

## 2. 部署ごとの課題と期待

| 部署・発言者 | 課題 | 期待・優先したいこと |
| --- | --- | --- |
| 総務部 高橋部長 | 購入申請から登録までが分断され、登録漏れが出る | 「まず所在が分かる状態にしたい。貸出管理がちゃんとできれば十分効果がある」 |
| 総務部 松本主任 | 貸出中の備品の所在が追えない。棚卸の負荷が大きく差異を説明できない | 既存Excel台帳のデータを移行したい |
| 経理部 中村課長 | 固定資産台帳と備品台帳が別管理で、突き合わせに手間がかかる。棚卸の負荷 | 「棚卸を楽にしたい。できれば固定資産台帳と紐づけたい」 |
| 情報システム課 小林係長 | 業務PC等を二重管理したくない | 社内アカウント（Microsoft 365）でログインしたい。SSOが必須かは情シス内で確認 |
| 製造課（欠席） | 工具・測定器を独自に管理 | 未確認。校正期限管理が必要かは製造課の意見次第 |
| 出席者全員 | — | スマートフォンでQRコード（またはバーコード）を読み取り、貸出・返却・棚卸をしたい |

## 3. 決まったこと

1. 要件定義を当社が支援する方向で進める（正式な契約・見積りは別途）。
2. 顧客窓口は総務部 松本主任。
3. 消耗品（文房具・トナー等）の在庫管理は対象外。

## 4. 決まっていないこと（論点）

当社の整理として、第2回打ち合わせで決めたい順に4つの論点にまとめた。個々の確認事項は [確認項目一覧](02_確認項目一覧.md) にある。

1. **誰が決めるか**: 最終判断者は高橋部長の見込みだが正式には未確認。2〜4を決める人なので最初に確定したい。
2. **何を第一段階にするか**: 総務は貸出管理、経理は棚卸・固定資産連携を優先している。初回では結論を出していない。
3. **何を対象にするか**: 工場の工具・測定器、業務PC・ネットワーク機器を含めるか。「備品」の定義が部署で異なる。
4. **いつまでに何を使えるようにするか**: 2027年3月末の棚卸で使いたいという希望はあるが、全機能か棚卸に必要な機能だけかは未合意。要件定義自体の期限もない。

## 5. 注意したい点（当社の整理）

- 範囲が決まらないまま期限だけが先に決まっている。範囲が膨らむと3月末に間に合わない恐れがある。
- 片方の部署の発言だけで範囲を決めない。総務・経理の両方の要望を並べたうえで、判断者に優先度を決めてもらう。
- 既製SaaSは「測定器の校正期限管理ができない」「固定資産台帳との連携が弱い」ことで見送られている。この2点を本当に必要とするかで、作るものの性格が変わる。
- データ移行は、台帳の一致率が7〜8割で番号重複もあるため、クレンジングの担当と時期を早めに決める必要がある。
